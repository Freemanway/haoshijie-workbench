# 上线手册

一期部署在境内云（阿里云或腾讯云）的一台云服务器上，数据库用云数据库，大模型用境内已备案的模型。部署包在 `deploy/` 目录：接口服务和前端各一个镜像，用 `docker compose` 启动。

## 一、上线前要准备的东西

| 项目 | 要求 | 谁来办 |
| --- | --- | --- |
| 云服务器 | 境内地域，2 核 4G 起，Ubuntu 22.04 或 Alibaba Cloud Linux 3，装好 Docker | 管理员 |
| 云数据库 | PostgreSQL 16，开启 `vector` 插件（pgvector），开自动备份（保留 7 天以上），只允许云服务器内网访问 | 管理员 |
| 域名和证书 | 已完成 ICP 备案的域名（如 `ai.好时节域名`），HTTPS 证书 | 管理员 |
| 企业微信自建应用 | 企业 ID、应用 AgentId、Secret；“网页授权及 JS-SDK”和“企业微信授权登录”的可信域名填上面的域名；“接收消息”里生成 Token 和 EncodingAESKey | 企业微信管理员 |
| 大模型 | 境内已备案模型的 API Key（当前选 DeepSeek），按厂商当前价格记下单价 | 管理员 |
| 镜像源 | 云厂商的容器镜像服务里准备 `node:22-alpine`、`nginx:1.27-alpine`（境内拉 Docker Hub 不稳定） | 管理员 |

## 二、部署步骤

```bash
# 1. 拿代码
git clone https://github.com/Freemanway/haoshijie-workbench.git && cd haoshijie-workbench

# 2. 填配置：以 .env.example 为模板，生产值写进 deploy/server.env（这个文件不进代码仓库）
cp .env.example deploy/server.env
#   必改：DATABASE_URL（云数据库内网地址）、JWT_SECRET（openssl rand -hex 32）、
#         FIELD_ENCRYPTION_KEY（openssl rand -base64 32）、AUTH_DEV_LOGIN=false、
#         WECOM_*、WEB_ORIGIN 和 API_ORIGIN（都填 https://你的域名）、LLM_API_KEY、LLM_PRICE_*、
#         SEED_ADMIN_WECOM_ID（首位管理员的企业微信账号）
#   FIELD_ENCRYPTION_KEY 上线后不能再改，否则已存的手机号、地址解不开；另存一份到云 KMS 或密码库。

# 3. 构建镜像（基础镜像换成自己镜像仓库里的地址）
cd deploy
docker compose -f docker-compose.prod.yml build \
  --build-arg NODE_IMAGE=registry.cn-hangzhou.aliyuncs.com/<命名空间>/node:22-alpine \
  --build-arg NGINX_IMAGE=registry.cn-hangzhou.aliyuncs.com/<命名空间>/nginx:1.27-alpine

# 4. 建表、初始化（首位管理员、风控词库、知识库样例）
docker compose -f docker-compose.prod.yml run --rm server pnpm prisma:deploy
docker compose -f docker-compose.prod.yml run --rm server pnpm db:seed

# 5. 自检：配置、迁移、成员、账号、知识库、词库、基线，有“✗”项要先处理
docker compose -f docker-compose.prod.yml run --rm server pnpm preflight
docker compose -f docker-compose.prod.yml run --rm server pnpm llm:check

# 6. 启动
docker compose -f docker-compose.prod.yml up -d
curl -s http://127.0.0.1:8080/api/health   # {"status":"ok","database":"up",...}
```

前端容器只监听本机 8080 端口，HTTPS 在宿主机 nginx（或云负载均衡）上配置：

```nginx
server {
  listen 443 ssl http2;
  server_name ai.example.cn;               # 换成备案域名
  ssl_certificate     /etc/nginx/cert/fullchain.pem;
  ssl_certificate_key /etc/nginx/cert/privkey.pem;
  client_max_body_size 20m;
  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;
    proxy_read_timeout 120s;
  }
}
server { listen 80; server_name ai.example.cn; return 301 https://$host$request_uri; }
```

## 三、企业微信里的配置

- 应用主页：`https://域名/overview`；客服在手机上接待用 `https://域名/m/inbox`，可以加到应用的自定义菜单。
- 扫码登录回调：`https://域名/api/auth/wecom/callback`。
- 接收消息（加微回调）：URL 填 `https://域名/api/wecom/callback`，Token 和 EncodingAESKey 与 `server.env` 里的 `WECOM_CALLBACK_*` 一致；保存时企业微信会校验一次，服务要先启动。
- 客户联系“可调用应用”里勾选这个自建应用，渠道活码才能建出来。

## 四、上线后在工作台里做的事

1. 管理员扫码登录，在“成员与权限”添加客服、招商、内容运营、审核人和管理层；停用测试账号。
2. “平台账号”添加小红书账号，设好每日发布上限和私信接入方式（一期是半自动）。
3. “品牌知识库”补齐产品、产地、价格口径、配送范围和不发货地区、售后规则；FAQ 至少覆盖价格、配送、保存、售后。
4. “收件箱 > 接待设置”按客服排班填工作时间和转人工时限。
5. “数据周报 > 对比上线前基线”录入人工方式下的基线和目标（见 PRD 11.2）。
6. 再跑一次 `pnpm preflight`，全部必需项通过。

## 五、运行和维护

- **备份**：数据库靠云数据库的自动备份，另每周手动导出一次留存；`server.env` 和加密密钥单独保管。
- **监控**：云监控对 `https://域名/api/health` 配站点监控，连续 3 次失败告警到管理员手机；接口容器自带健康检查，异常会自动重启。
- **日志**：`docker compose -f docker-compose.prod.yml logs -f server`，单个日志文件 50MB、保留 5 个。
- **发版**：`git pull` → `build` → `run --rm server pnpm prisma:deploy` → `up -d`。发版前给当前镜像打标签（`docker tag hsj-server hsj-server:上一版`），出问题改回上一版镜像再 `up -d`。数据库迁移只增不删，回滚镜像不需要回滚数据库。
- **咨询高峰**：私信处理并发由 `INBOX_CONCURRENCY` 控制，默认 8。估算方法和压测数据见 [压测记录](压测记录.md)；高峰前按预计咨询量重跑一次压测。
- **单实例**：任务队列在进程内，一期只跑一个接口容器；要扩到多台时先把队列换成 Redis + BullMQ（技术方案已选型）。
